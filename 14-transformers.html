Transformers, End to End

One architecture now runs text, code, images, audio and protein folding. It is a stack of identical blocks, each doing exactly two things: mix information across positions (attention), then think about each position independently (an MLP). Everything else is detail — but the details are where the systems work lives.

The block

A modern decoder block, in the order data flows through it:

Inside one transformer blockStep-through
  1. A matrix of T token representations, each of width d (the “model dimension” or residual stream). For a 7B model, d is typically 4096 and there are 32 blocks.
  2. Pre-norm: normalize before the sub-layer, not after. This keeps the residual path clean and makes deep stacks trainable without an elaborate warmup (Chapter 9).
  3. Three linear maps produce queries, keys and values — each d×d, so this is 3d² parameters. They are then split into heads, each working in a d/h-dimensional subspace.
  4. Per head: softmax(QKᵀ/√dₕ + mask)V. This is the only operation in the whole block where positions talk to each other. Everything else is per-token.
  5. Head outputs are concatenated and passed through a final d×d output projection, which lets the model mix what different heads found.
  6. Add the sub-layer output back to its input. The residual stream is a running “working memory” that every block reads from and writes to — and the identity path is what lets gradients reach block 1.
  7. Second pre-norm before the feed-forward sub-layer.
  8. Expand d → 4d, apply a nonlinearity, project back. No mixing across positions at all. This is where roughly two-thirds of the parameters live, and where much of the model's factual knowledge appears to be stored.
  9. Add again, and hand the result to the next identical block. Thirty-two repetitions later, a final norm and a projection to vocabulary logits produce next-token probabilities.
🧵
The residual stream mental model

Think of the residual as a shared bus of width d running the height of the model. Each attention sub-layer reads from the bus, gathers information from other positions, and writes a correction back. Each MLP reads, computes something local, and writes back. Nothing is ever replaced — only added. That framing explains why techniques like LoRA (low-rank additions) and activation steering work at all.

Multi-head attention

Instead of one attention with dimension d, run h attentions of dimension d/h in parallel. Same total compute, but each head can specialise: one tracks syntax, another matches previous mentions, another attends to the delimiter at the start.

Why several heads

A single softmax produces one distribution — it must choose one thing to look at. Eight heads can look at eight different things at once and combine the results. Empirically many heads are redundant and prunable, but the capacity to attend to multiple relations per layer clearly matters.

MQA and GQA

The KV cache dominates inference memory, so modern models share keys and values across heads: multi-query (one K/V for all heads) or grouped-query (one per group of 8). This shrinks the cache by 8–64× with minimal quality loss — a pure systems-driven architecture change.

Where does position come from?

Attention is permutation-invariant: shuffle the tokens and the same set of values comes back. Order has to be injected explicitly.

🔄
RoPE in one sentence

Rotating query and key vectors by position-dependent angles makes their dot product depend only on the difference of their positions — so relative distance falls out of the geometry instead of being learned per absolute slot. That's also why you can stretch context by scaling the rotation frequencies (“RoPE scaling”), which is how 4k-trained models get extended to 32k+.

Three family shapes

📖

Encoder-only

Bidirectional attention, trained by masked-token prediction. BERT-style. Best for classification, extraction and embeddings — every retrieval system in Chapter 20 uses one.

✍️

Decoder-only

Causal attention, next-token prediction. GPT/Llama-style. Generates text, and is what “an LLM” means today. Scales best and is the simplest to train.

🔁

Encoder–decoder

Encode input bidirectionally, decode output causally with cross-attention. T5/Whisper-style. Natural for translation and speech, where input and output are distinct sequences.

Inference: prefill, decode, and the KV cache

Generation has two very different phases, and conflating them is the most common cause of bad inference design.

1️⃣ Prefill

Process the whole prompt in one parallel pass. Compute-bound, high arithmetic intensity, efficient. Cost scales with prompt length (and quadratically for attention).

2️⃣ Decode

Generate one token at a time, each depending on the last. Memory-bound and sequential: every step re-reads all the weights to produce a single token (Chapter 10).

Recomputing attention over the entire prefix for every new token would be quadratic per token. Instead, keys and values for past tokens are cached — the KV cache — and only the new token's Q, K, V are computed. That turns decode into a linear-cost step, at the price of a lot of memory.

⚠️
Common mistakes
  • Thinking the MLP is a minor part. It is roughly two-thirds of the parameters and most of the FLOPs — attention gets the attention, the MLP gets the compute.
  • Sizing a GPU by weights only. The KV cache at high concurrency often exceeds the model itself.
  • Using temperature > 0 for structured output and then parsing failures as “model errors”.
  • Assuming longer context is a free upgrade. Quadratic attention, linear KV growth, and measurable quality decay in the middle of long inputs.
  • Forgetting that decode is sequential. Latency scales with tokens generated; the only real levers are fewer tokens, smaller models, or speculative decoding (Chapter 27).

Interview drill

Warm-up: Why does a transformer need positional encodings when a CNN and an RNN don't?

How a strong answer sounds
Attention computes a weighted sum over a set — permuting the inputs permutes the outputs identically, so order carries no information. An RNN gets order from the sequential recurrence; a CNN gets locality from the kernel's spatial layout. A transformer has neither, so position must be injected: added to embeddings (absolute) or built into the attention score (RoPE, ALiBi). RoPE is the modern choice because it makes the score depend on relative distance, which generalises better and can be stretched for longer contexts.

Deeper: Estimate how many concurrent 8k-context users a single 80 GB GPU can serve with a 7B model, and say what you'd change to double it.

How a strong answer sounds
Weights in bf16 are ~14 GB, leaving ~60 GB after workspace. With 32 layers, d=4096, MHA and fp16 cache, KV is roughly 2×32×4096×2 bytes ≈ 0.5 MB per token, so 8k tokens ≈ 4 GB per request — about 15 concurrent users. To double it: switch to grouped-query attention (8× smaller cache — the single biggest win), quantize the KV cache to fp8, use paged attention so memory isn't wasted on partially-filled blocks, and quantize weights to int8/int4 to free several more gigabytes. Beyond that, shorten prompts with retrieval instead of stuffing context, and enable prefix caching for shared system prompts.

🧠 Key takeaways

  • A block = pre-norm → attention (mixes positions) → residual → pre-norm → MLP (per-token) → residual.
  • Attention holds ~4d² parameters per block, the MLP ~8d² — most of the model is the MLP.
  • Position is injected explicitly; RoPE encodes relative distance and is the modern default.
  • Inference splits into compute-bound prefill and memory-bound decode; the KV cache makes decode linear but dominates memory.
  • Params ≈ 12·d²·layers; training ≈ 6ND FLOPs; inference ≈ 2N FLOPs per token.

Check your understanding

Which part of a transformer block mixes information between token positions?

Everything except attention operates on each position independently. That's why attention is the only place masking is needed — and the only place context length shows up in the cost.

What is the KV cache for?

Without it, each new token would recompute attention over the whole prefix. With it, decode is linear per token — but the cache grows with context × concurrency and usually limits how many users a GPU can serve.

Why do modern models use grouped-query or multi-query attention?

Sharing keys and values across heads cuts cache size by the sharing factor — an architecture decision driven almost entirely by serving economics.

You need strict JSON output from a model. Which setting is most appropriate?

Determinism removes a whole class of parse failures, and constrained decoding masks tokens that would violate the grammar — turning “usually valid” into “always valid”.

Roughly how many FLOPs does training a 7B model on 2T tokens require?

6 × N × D = 6 × 7e9 × 2e12 ≈ 8.4e22. At ~1e15 useful FLOP/s per GPU that's roughly 1,000 GPU-days — the arithmetic behind every frontier training budget.
